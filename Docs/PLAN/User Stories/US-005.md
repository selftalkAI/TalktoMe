# US-005 — Brain 2 Reply Quality: Five-Step Pipeline with Check

**Status:** Ready
**Priority:** MVP / must-have (first to build)
**Related requirements:** `FSD FR-B2-001` – `FR-B2-008`, `BR-016`
**Related architecture:** `ADD §8.2`, `ADD ADR-019`, `ADD ADR-022`, `TDD §5.4`
**Spec:** `Docs/FEATURES/Building_Brain2.md` §7–§9, §12

## Story

As a user talking to selfie.Me,
I want every reply to be short, specific to me, and genuinely helpful,
so that it feels like talking to someone who knows me — not a bot reading a template.

## Description

Replace the single Broca call with Understand → Decide → Speak → Check → Remember. Check rejects bad replies before the user sees them. Chat replies stop being stored as "Profile draft v1"; profile proposals become separate and rare.

## Acceptance criteria

- **Given** any of the real bad outputs listed in `Building_Brain2.md` §2, **when** run through Check, **then** each is rejected.
- **Given** a reply candidate with headings, bullet lists, "the user", meta-talk, more than one question, a number not in the context, or a sentence repeated from the last five replies, **when** checked, **then** it fails.
- **Given** all candidates fail twice, **when** the turn completes, **then** a safe fallback (a short reflection plus one open question) is sent instead.
- **Given** the user asked a question, **when** Decide plans the reply, **then** the plan answers it first.
- **Given** a normal chat turn, **when** it completes, **then** no `profile_entries` row is created unless Remember judged that something lasting was learned.
- **Given** a turn, **when** it completes, **then** its understanding, plan, candidates and check results are recorded for observability.
