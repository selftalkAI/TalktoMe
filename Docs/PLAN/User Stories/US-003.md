# US-003 — Emotional Support Agent: Five Core Response Aspects

**Status:** Draft
**Priority:** Post-MVP (depends on `US-001`, `US-002`)
**Related requirements:** `FSD FR-SAFE-005`, `FR-SAFE-008` (crisis handling), `FR-CONV-005`, `FR-CONV-006`
**Related architecture:** `ADD §6` (personal context layers), `ADD §14` (AI safety and grounding), `US-001` (Persistent Memory), `US-002` (Memory Layer Mechanism)
**Related knowledge base:** RAG-ingested psychology framework summaries (see Notes) — ingested via `POST /api/v1/rag/documents`, retrieved via `GET /api/v1/rag/retrieve`

## Story

As a user going through a difficult moment,
I want the assistant to recognize what I'm actually feeling, make me feel heard, help me see the situation more clearly, help me move toward action, and connect it back to what matters to me,
so that the support I get feels like it understands me, not like a generic chatbot response.

## Description

Synthesizing across ten psychology/self-help references (Goleman, Rosenberg, Miller & Rollnick, Dweck, Frankl, Kahneman, Neff, Clear, Burns, Csikszentmihalyi), the emotional agent's response behavior reduces to five ordered aspects. Each response should move through them in sequence — skipping straight to advice without validating first is the most common failure mode this story exists to prevent.

| # | Aspect | Question it answers | Primary knowledge source(s) |
|---|--------|---------------------|------------------------------|
| 1 | **Recognize** | What is the person actually feeling, and what's underneath it? | Emotional Intelligence, Thinking Fast and Slow, Feeling Good |
| 2 | **Validate** | Have I made them feel heard before trying to help? | Nonviolent Communication, Self-Compassion, Motivational Interviewing (reflective listening) |
| 3 | **Reframe** | Can I help them see this more accurately, not just more positively? | Feeling Good (cognitive distortions), Mindset, Thinking Fast and Slow |
| 4 | **Motivate** | How do I help them move from stuck to a next step, without pushing? | Motivational Interviewing, Atomic Habits, Mindset, Flow |
| 5 | **Anchor to meaning** | How does this connect to who they are and what matters to them? | Man's Search for Meaning, Flow, Motivational Interviewing, Atomic Habits |

This story is deliberately built on top of, not instead of, the existing memory infrastructure: aspects 1 and 3 write to typed memory categories (`emotional_pattern`, `mindset_pattern`, `thinking_pattern`); aspects 4 and 5 read from `goal`, `routine` (habit), `relationship`, and `event` memories already defined in `memory_repo.VALID_TYPES` (`US-002`); and all five aspects draw supporting technique/framework knowledge from the RAG knowledge base, not from raw book text (see Notes on copyright).

## Acceptance criteria

- **Given** a user message, **when** the agent responds, **then** the response follows the Recognize → Validate → Reframe → Motivate → Anchor order — validation is never skipped in favor of jumping straight to advice.
- **Given** a message where the surface emotion differs from the underlying one (e.g., "whatever, I don't care" masking hurt), **when** the agent recognizes the emotion, **then** it identifies the underlying feeling and need, not just the literal words, and this reading is checked against the person's own history in memory (is this a recurring pattern?) before being treated as confident.
- **Given** a recognized emotion and need, **when** the agent validates, **then** it reflects the feeling back in its own words before offering any suggestion, and never responds with dismissive positivity ("just stay positive," "others have it worse").
- **Given** a message containing a cognitive distortion (catastrophizing, all-or-nothing thinking, labeling, overgeneralization), **when** the agent reframes, **then** it names the pattern internally, questions it with a Socratic question rather than a correction, and only does so after validation has already happened.
- **Given** a person expressing they feel stuck, **when** the agent motivates, **then** it asks rather than lectures, and any suggested action is the smallest next step, optionally tied to the person's stated identity/goals from memory.
- **Given** a hard moment (loss, grief, feeling lost), **when** the agent anchors to meaning, **then** it draws on the person's own stored values, goals, important people, or past resilience — never a generic inspirational statement disconnected from their actual history.
- **Given** a message plausibly indicating self-harm, suicidal ideation, or abuse, **when** any of the above five aspects would otherwise run, **then** they are bypassed entirely in favor of the reviewed crisis-response script and professional resources (`FR-SAFE-008`) — this check runs first, before Recognize.
- **Given** the agent is asked something requiring professional judgment (diagnosis, medication, legal/financial advice), **when** it responds, **then** it states its scope honestly (a supportive companion, not a therapist) rather than answering as if qualified to.
- **Given** the RAG knowledge base is queried for a technique (e.g., "how to respond to catastrophizing"), **when** retrieval runs, **then** it returns the team's own summarized framework notes, never verbatim copyrighted book text.

## Out of scope for this story

- Fine-tuning or training a custom model — this is a prompting + retrieval + memory pattern, not a model training effort.
- The actual knowledge base content (book summaries, technique notes, example phrases) — tracked separately; this story assumes it exists once provided.
- A dedicated `EmotionalAgent` implementation — whether this becomes a new agent or a mode on the existing `SmartAgent` is an implementation decision for when this story is picked up.

## Notes

- **Copyright**: the ten source books must never be ingested as full text into the RAG store. Only original summaries, structured framework notes, and freely licensed material (e.g., NVC's published feelings/needs lists, open-access research on Motivational Interviewing / Self-Determination Theory / growth mindset) may be ingested.
- **Non-negotiable safety guardrail**: crisis detection is not one of the five aspects — it is a gate that sits in front of all of them, consistent with the existing `FR-SAFE-008` crisis-disclosure handling already required for the MVP.
- Suggested new persistent-memory tags to support this story: `emotional_pattern`, `mindset_pattern`, `thinking_pattern` — these would need to be added to `memory_repo.VALID_TYPES` (`US-002`) when this story is implemented, since the current type set (fact, preference, goal, relationship, event, routine, constraint, project_context, user_instruction) doesn't yet cover them.
